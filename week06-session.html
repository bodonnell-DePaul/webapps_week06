Entity, attribute, key — the three words you need

  • Entity: a thing with a life of its own — service, building, incident, user
  • Attribute: a fact about one entity — a name, a slug, a created_at
  • Primary key: the one column that names exactly one row, forever
  • Surrogate key (service_id) for identity; natural key (slug) gets a unique index
  • Foreign key: a rule the database enforces — "this update belongs to a real incident"

✦Tip

Test for entity vs attribute: does it have facts of its own, or relationships to more than one thing? Then it is an entity.

Fictional CampusPulse case: the migration nobody read

What happened

  • A teammate renames owner_team to owning_team in the model class
  • The ORM generates a migration; it is applied unread
  • The SQL was DROP COLUMN then ADD COLUMN
  • Every service's owner is now empty in production

What would have caught it

  • Reading the generated SQL before applying it
  • A NOT NULL constraint that made the migration fail loudly
  • A staging run against a copy of real data

What an ORM does, and what it hides

◆Key idea

Use the left column. Inspect the right one before production does.

Does for you

  • Maps classes or objects to tables and rows
  • Builds parameterized SQL — no string concatenation
  • Tracks changes and saves them in one transaction
  • Generates migrations from model changes

Hides from you

  • How many queries a page actually runs
  • Which indexes exist, or do not
  • What the generated DDL really does
  • Where one transaction ends and the next begins

Reviewing a schema your assistant generated

  • Does every table have a deliberate primary key, and every relationship a foreign key?
  • Are unique constraints on what humans type (slug, email)?
  • Are there indexes for the queries the product actually runs?
  • Are timestamps, soft delete, and lookup tables there — the six rules?
  • Is any derived or duplicated value stored without a detector?
  • Did it put secrets or personal data where they do not belong?

▲Watch out

AI can draft a schema in seconds. It cannot know your access patterns, your retention rules, or which column your audit trail depends on.
